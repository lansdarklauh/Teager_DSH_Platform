## 2. 建议采用的业务边界

“管理员”建议明确为平台角色 `PlatformRole.Admin`。普通用户即使历史上具有 Pool Admin/Owner、Workspace Admin/Owner 或共享空间 MANAGE，也不能因此获得空间管理能力。

普通用户登录后默认进入自己的工作空间，提供任务会话、私有文件管理、终端与命令执行、用户级依赖安装、自有应用及进程管理、经授权的共享资源、个人 API Token 与开发说明、个人设置。个人存储、计算与模型用量嵌入工作台；全平台治理页面仅管理员使用。

用户可以在自己的可写目录内自由创建、修改、移动、删除文件，运行脚本、构建项目、安装依赖和启动服务，体验接近独立开发机。边界同时包括文件系统、进程、凭据、网络和配额：不能访问其他用户环境、修改只读共享资源、获得宿主管理权限或绕过平台模型与资源策略。平台配置、运行镜像、授权及空间生命周期仍由管理员管理；用户自己的应用配置和依赖由用户管理。

必须区分三种状态：

1. **无访问授权**：资源不可见，不能读取；访问资源 ID 返回 404。
2. **有访问授权，未获编辑授权**：只读，可以浏览和下载授权范围内文件。
3. **管理员明确指派编辑权限**：可编辑指定内容，但不能创建空间、分配权限、调整配额或管理结构。

“没有权限的用户只读”应理解为“没有编辑权限、但已有访问权限的用户只读”，不能让完全未授权的用户读取所有空间。

“自己的工作空间”建议定义为管理员或系统分配给该用户的个人工作空间，而不是由用户创建的空间，也不是所有因 Pool 成员关系而继承可访问的空间。建议默认一人一个个人工作空间，模型保留以后由管理员分配多个的能力；本期普通用户不能进入他人的任务工作空间。

Pool 是组织和资源分组，没有独立的任务文件区。若保留“Pool 可编辑”的需求，建议只允许管理员指派的编辑者修改名称、描述等展示信息；成员、层级、工作空间、共享空间授权、策略、模型、MCP、密钥和 Runtime 仍全部由平台管理员管理。Pool 的编辑授权不会自动赋予其下工作空间和共享空间的读写权。

## 5. 后端改造

### 5.1 将资源管理与内容使用拆开

- 在服务层统一校验平台管理员，再由 Controller 校验 Token Scope。所有创建、克隆、空间生命周期、成员、授权、挂载、策略、配置、密钥和 Runtime 管理写入口都覆盖到。
- `PermissionEngine` 输出明确能力，例如 `canView`、`canEditContent`、`canExecute`、`canManageResource`、`canManageMembers`；前端消费相同结果。
- 普通用户旧 Owner/Admin/MANAGE 记录不得成为管理能力的来源。无权读取返回 404，已可见但操作能力不足返回 403；禁止创建返回 403。
- 全局会话搜索、会话详情、消息、导出、SSE 历史/订阅、取消任务、文件历史版本及快照都必须复用新的个人空间访问规则。
- 审查只读响应：Pool 树计数、成员名单、共享授权名单、挂载候选、用量和配置详情不得泄露其他用户空间、被拒绝共享空间或组织管理信息。`users/lookup` 建议仅管理员可用。
- 普通用户使用平台 Agent 时只能选择管理员允许的模型，不得修改平台托管模型、MCP、Skill、插件和命令配置，或借由本地文件覆盖平台强制策略。用户自己的程序、脚本、依赖和应用配置允许在个人环境内编辑执行；调用自有外部服务使用用户自己的凭据，并遵守网络策略。有效平台配置接口向普通用户返回经裁剪的使用字段。

### 5.2 个人工作空间归属与分配

- 为 Workspace 增加个人/协作类型和个人归属用户字段，例如 `Kind`、`AssignedUserId`。不得使用 `CreatedBy` 判断归属，管理员代建时创建人与使用人不同。
- 为用户维护默认工作空间映射，例如独立的 `UserWorkspaceAssignment`（含 `IsDefault`），并保证每个用户最多一个有效默认空间。归属与默认映射必须保持一致。
- 个人 Workspace 固定 `InheritPoolMembers=false`；普通归属用户获得 Member/明确任务能力，不授予 Owner/Admin 管理能力。
- Workspace 所属 Pool 由管理员指定，用于 Runtime、配置、配额和共享资源组织；用户不需要成为 Pool 管理员才能使用其个人空间。
- 创建普通用户时，由可信系统分配流程在事务中建好个人空间和默认映射；用户不能调用通用创建接口。并发分配必须幂等，有唯一约束，失败可重试并清理未完成的目录。
- 对既有用户先做迁移分配；登录时只校验已有分配，缺失时走受控补齐流程或显示“尚未分配，请联系管理员”，不能使用户可自行选 Pool 或建空间。
- 登录响应及 `/auth/me` 返回默认空间 ID 与使用能力。一个个人空间直接进入工作台；以后多个分配空间时提供受限切换器。
- 服务账号不自动创建可交互个人空间；由管理员明确绑定可调用的工作空间。

### 5.3 共享空间及 Pool 的编辑授权

- 共享空间复用现有 `SharedSpaceGrant`：Pool 基础授权 RO，管理员对指定用户增加 USER/RW；没有 USER/RW 的普通用户最多 RO。
- 显式 Deny 仍优先，任一适用链路的拒绝不能被用户 RW、挂载或 Token 抵消；撤销用户 RW 后，若仍有可见性授权则降为 RO，否则完全不可见。
- 共享空间管理权只给平台管理员，普通用户不能授予 RW、MANAGE 或修改他人权限。
- Pool 新增独立的“展示信息编辑”能力，不复用现有 Pool Admin/Owner；也不要让新的枚举值通过数值比较转换成 Workspace 高权限。
- Pool 编辑只开放名称/描述字段，其余字段即使通过手工请求提交也拒绝。编辑不向子 Pool、Workspace 或共享空间继承。
- 个人用户授权与挂载规则统一：建议管理员在个人 Workspace 所属 Pool 建立共享资源的挂载资格，并在用户层裁决最终 RO/RW/Deny。直接 API、文件区域与 Agent 挂载使用同一个计算结果；仅用户授权但无挂载资格时允许直接访问，不自动挂载。
- 挂载覆盖只降不升。用户获得 RW 后，如果管理员将该 Workspace 的挂载固定为 RO，则该路径仍只读。
- 在管理员界面提供可见用户/只读用户/编辑者名单和授权来源，赋权、降权、撤权均留审计。

### 5.4 API Token 与开发说明

- 保留现有 Token 页面，普通用户仅创建个人/临时 Token，查看与吊销自己的 Token；服务 Token 仅管理员创建。
- 普通用户默认 Token 绑定自己的个人 Workspace，禁用“空白名单表示不限”和按整个 Pool 扩大 Workspace 范围的创建方式。后端必须验证，不能只限制表单。
- 默认 SDK Scope 为 `workspace:read`、`session:read/create/execute`、`files:read/write`；只读预设按用途进一步收窄。
- 普通用户禁止管理 Scope：`pool:manage`、`workspace:manage`、`share:manage`、`runtime:manage`。`workspace:execute` 可供普通用户显式勾选，仅用于直接命令/终端执行，并绑定自己的 Workspace；默认 SDK Token 不自动包含此 Scope。现有 `workspace:write` 涵盖创建和元信息写入，不能用它代表普通任务文件写权限。
- `session:execute` 允许平台 Agent 执行任务，任务可能使用 shell 工具；它不等价于“禁止执行命令”的 Token。`workspace:execute` 区分的是直接命令/终端入口；若以后需要真正的无执行 Token，必须同时去掉 Agent 执行能力。新增进程控制和应用预览接口的 Scope 在接口契约中明确，不能由单纯文件读写权隐式取得。
- 如要通过 API 直接使用授权共享空间，增加明确共享资源白名单（例如 `AllowedSharedSpacesJson`）及相应 `share:read/write`，只能选择管理员已授权的资源；默认个人工作空间 Token 不包含该额外范围。
- 所有 Token 请求取“当前用户能力 ∩ Scope ∩ 资源白名单 ∩ 当前授权/挂载限制”。Token 不固定保留已撤销的 RW；旧 Token 也必须受新能力上限约束。
- 执行类 Token 的运行挂载、代理凭据和进程权限必须按该 Token 的交集生成，不能直接接入已有 Web 全权限终端、复用更宽授权的运行环境或挂载。默认不含共享范围的 Token 所启动的 Agent/命令不挂载共享资源；包含共享访问时继续要求对应共享 Scope、资源白名单和当前 RO/RW 权限。不同执行凭据需隔离进程与挂载上下文，持久化个人文件可以共用，不能共用平台身份凭据。
- 任意 shell/Agent 执行可以读写其可写目录，不能声称只有 `files:read` 的执行 Token 仍然只能读。此次执行预设要求同时具有个人 `files:read/write`，缺失时拒绝开启执行；真正只读预设不含执行 Scope。个人文件中用户自行保存的凭据仍可被该用户执行环境读取，应在文档明确，不能承诺 Scope 会隔离用户主动放入文件的秘密。
- Pool 编辑者若需 API 编辑 Pool 展示字段，应使用独立细粒度能力/Scope；不能为此发放通用 `pool:manage`。
- Token 明文继续仅创建时显示一次；日后显示前缀、名称、有效期、范围和状态。丢失后吊销并重新创建，不保存可回读明文。
- 补全开发说明：实际 API Base URL、个人 Workspace ID、Scope 说明、创建会话、发送消息并等待结果、查询/取消任务、SSE 断线续接、文件上传下载、Python SDK 安装和调用、401/403/404/429、配额与授权共享空间示例。新增命令执行、终端连接、自己的进程管理和应用预览契约及示例，标明新增接口待实现，不能作为当前已有功能发布。
- 示例自动填入个人 Workspace ID，Token 用占位符或本机环境变量，不把真实 Token 写入 URL、示例文件或日志。

### 5.5 个人运行环境与真实隔离边界

当前 DSH 子进程工作目录位于 Workspace，共享目录使用链接挂载；修改工作目录和提示词不能形成文件系统访问边界。源代码没有在该挂载层按 RO/RW 设置独立的系统权限；不能据此保证只读目录不可修改或无法用绝对路径访问其他 Workspace。

- 按个人 Workspace 隔离运行环境、系统身份、进程可见范围和 DSH 会话存储。仅映射该用户私有文件、用户 home/依赖目录 RW，及已授权共享目录 RO/RW；平台控制文件和基础镜像只读。不映射其他用户目录、宿主数据根目录、容器控制 socket 或通用管理凭据。
- RO 必须由只读卷、隔离账户 ACL 或等效的操作系统/容器权限实现；RW 仅对指定共享目录放行。现有 Pool 级 DSH_HOME 也需检查会话状态和凭据隔离，不能暴露其他用户会话。
- 结合项目 Windows 本地与 Docker 部署选择可验证的隔离实现；仅复制 RO 内容到可写目录不等于完整隔离，若宿主真实目录仍可访问就仍有绕过通道。
- 普通用户交互终端作为正式使用能力交付；终端、Agent shell/文件工具、API 命令和后台应用使用同一隔离边界。用户不得提升为宿主管理员、修改隔离边界或重新挂载 RO 目录，不以命令黑名单或提示词代替隔离。
- 平台模型密钥、服务 Token、数据库连接及管理凭据不进入用户可读的进程环境、配置、日志或 DSH_HOME。由隔离环境之外的可信代理持有上游密钥，用户运行仅取得短期、绑定 Workspace/Run 和用途的受限凭据；代理实时校验模型策略、授权、吊销和用量。配置目录只读仍可被读取，不能用只读代替密钥隔离。
- 用户自己的应用凭据按个人秘密管理，与平台密钥分开存储和授权；使用用户自己的终端应视为可以读取自己应用所使用的秘密，不能承诺同一执行身份内对秘密保密。
- 无法提供隔离的部署方式不满足本方案；后端阻止其普通用户 Agent、终端、命令和后台应用执行，并明确报告环境未就绪。此项是上线保护，不是最终默认关闭普通用户终端的产品设计。
- 权限变更后立即让后续 API/任务使用最新权限；已运行任务、应用进程、SSE/终端连接、应用预览及已挂载目录必须撤销对应访问，必要时停止受影响的进程并重建运行环境。账号禁用时终止其环境执行与访问。不能只清缓存而保留旧 RW 挂载。
- 多实例权限缓存应通过可共享的版本或失效通知同步；保留变更审计作为补充。

### 5.6 终端、依赖、应用进程与端口

- 提供隔离环境内的非特权交互终端，支持多终端会话、UTF-8、窗口调整、中断和显式关闭；命令执行仍校验当前账号、Workspace 归属和 API Scope。用户可以终止自己的命令/应用进程，不能停止平台控制进程或其他用户进程。
- Python venv、用户级包目录、npm 项目依赖和自己的构建工具安装到个人可写目录；基础镜像、宿主服务和系统配置由管理员管理。需要系统依赖时由管理员提供镜像能力或受控配置，不授予宿主 sudo/管理员权限。
- 私有文件、home 和依赖目录持久化；终端断线不删除数据。后台应用经进程监督器登记，记录所属 Workspace、启动者、状态、资源占用、日志与停止入口。取消 Agent Run 不误杀独立启动的应用；销毁环境时统一回收其全部进程和子进程。
- 默认断开终端或退出登录不立即结束已登记的后台应用；持续运行时长、空闲回收和重新启动由管理员策略决定，并提前在用户界面说明。短期 API Token 到期/吊销时关闭该 Token 的连接并停止其临时执行；持久应用需通过明确的持续运行授权启动，不能借后台启动变成无限期权限。
- 应用仅监听个人环境内的端口，经鉴权反向代理提供 Workspace 绑定的预览 URL；HTTP/WebSocket 均验证当前用户和资源范围，其他用户不能凭 URL 访问。禁止任意宿主端口映射；对外公开发布属于另外的管理员授权能力，不因启动服务自动获得。
- 用户应用预览采用与平台管理界面隔离的站点/域名，平台登录 Cookie 和管理凭据不转发给用户应用；预览票据绑定用户、Workspace、应用和有效期。防止用户运行的 HTML/脚本借平台同源身份调用管理 API，授权撤销时同步使预览票据和已有连接失效。
- 网络出口由管理员策略限制，可按需要开放包仓库和业务服务；阻止访问宿主控制面、数据库管理面、其他用户私网和云元数据等非授权目标。服务监听、网络出口与共享文件权限分别校验，不能以文件隔离代替网络隔离。
- 命令与应用使用真实磁盘配额和进程资源限制；只经文件 API 检查不能防止终端绕过。进程日志、依赖缓存和临时文件计入相应预算，用户可清理自己的内容，不能修改计量记录。

### 5.7 资源预算与运行状态

- 管理员配置 Workspace 的 CPU、内存、磁盘/文件数量、进程数、终端/任务并发、应用端口数、网络用量及持续运行时长；设定可配置的有限默认值，普通用户只能查看用量。
- 模型请求/Token 预算与环境计算/存储预算分别计量，Pool 总预算与个人预算取有效上限；超限明确拒绝、限速或终止对应执行，不静默占用宿主剩余资源。
- Agent Run 超时、一次命令超时、后台应用存活期分别定义。会话连接状态与环境/进程状态分开；用户可查看排队、启动、运行、结束及失败原因，异常重启后清理孤儿进程、释放名额并恢复状态。
- 允许终端、用户应用和 Agent 在同一个人文件区工作；明确普通文件并发写入可能冲突，编辑 API 可使用版本条件避免覆盖。平台配置/挂载物化必须受专用互斥或采用不可变目录，不能为了规避平台内部竞态而禁止所有用户应用并发。

## 6. 前端改造

- 普通用户导航：我的工作台、授权共享资源、API 接入、个人设置。Pool 可放入“授权资源”内以只读信息页展示，避免出现全功能“Pool 管理”入口；编辑者仅多出名称/描述编辑表单。
- 普通用户登录后跳转默认 Workspace；无分配时显示管理员分配提示，不展示“新建一个吧”等引导。
- 工作台增加终端、自己的进程列表、应用预览入口、环境状态和个人资源用量；显示依赖可安装位置、后台应用保留/回收规则与超限原因。支持关闭终端、停止自己的应用和查看日志，平台 Runtime 管理按钮仍只向管理员显示。
- 隔离环境未就绪时展示明确状态，后端同步拒绝执行，不能仅把终端按钮隐藏而仍允许 Agent shell 执行。
- 首页、Workspace 列表、Pool 列表/详情、共享空间列表/详情中的新建、克隆、删除、归档、恢复、成员授权、挂载配置及管理标签页按能力隐藏。
- 路由守卫保护管理员页面，并在 Workspace、Pool、共享空间详情加载时依据后端能力判断；通过直接 URL 访问也不能绕过。
- FileManager 已按文件列表响应的区域 `writable` 控制编辑、上传、建目录、删除和重命名，应保留并复用；切换区域、用户撤权后及时刷新能力，关闭旧编辑弹窗，新增移动/版本恢复 UI 也沿用该规则。
- RO/RW/Deny 展示一致，拒绝的共享空间不出现在普通用户资源列表及挂载候选中。
- Token 表单只显示允许的 Scope 和资源，移除普通用户“全部”和“整个 Pool/留空不限”；完善现有 `SdkSnippet`。
- 管理员界面补充分配默认个人空间、共享编辑者、Pool 展示编辑者、授权撤销及迁移状态。

## 7. 数据迁移与兼容

1. 先清点当前用户、Workspace 显式成员、Pool 角色、共享授权、挂载和 Token，输出迁移预览。不能仅按 `CreatedBy` 把管理员创建的空间都分给管理员。
2. 新增归属/默认映射和细粒度能力字段、索引及迁移，保留全部文件、会话和共享内容。归属有歧义的旧协作空间不自动改成某人的个人空间，由管理员分配；必要时另建个人空间。
3. 为普通用户分配默认个人空间，关闭个人空间的 Pool 成员继承；旧 Owner/Admin 记录受到统一的平台能力上限限制，不能继续获得管理权。
4. 清点旧 Pool/RW 和 USER/MANAGE 授权，避免上线后全员仍可写。按新规则收敛为基础 RO，仅保留管理员明确指派的 USER/RW。正式数据转换先生成明细和备份，不能删除内容。
5. 旧个人 Token 在新引擎中立即受能力上限限制；将空白名单/整 Pool 范围改为个人空间范围，提示对接方更新范围；确实无法安全映射的 Token 吊销并重新创建。
6. 停止或重建受新授权影响的运行任务、应用进程和连接，撤除旧目录链接/挂载，统一失效权限缓存。角色降级、账号禁用也必须覆盖 Token 与运行中的能力。迁移前列出停机影响，保留用户文件和依赖目录，不复制旧平台密钥到新用户环境；原有程序中的宿主路径需要迁移指引。
7. 新终端 Scope 按用途显式授予，不给旧 Token 批量扩权；清点旧 DSH_HOME、环境变量和配置内的凭据，迁出用户可访问区域。如确认旧平台密钥已暴露，再按密钥轮换流程处置。现有应用持续运行授权和状态必须显式迁移，不能把残留宿主进程视为新环境中合法的后台应用。
8. 发布顺序先启用后端限制与分配能力，再上线前端；若需分阶段发布，用受控能力开关，不能出现前端已限制而后端仍放行的窗口。普通用户执行能力上线必须同时满足隔离、密钥代理、配额和网络边界。
9. 回滚数据库/发布时保留文件和备份，但不应静默恢复普通用户的旧管理权限；回滚授权模型应由管理员单独评估。

## 8. 实施顺序与验收

| 阶段 | 内容 | 交付 |
| --- | --- | --- |
| P0-1 | 统一能力判定；所有创建/克隆/管理入口收紧；跨 Workspace 访问收敛 | 后端越权入口关闭 |
| P0-2 | 个人空间归属、默认分配、旧数据迁移及登录落点 | 用户登录有可用且独立的空间 |
| P0-3 | 共享 RO/RW 与 Pool 展示编辑授权；直接/挂载路径统一 | 编辑授权仅作用于指定资源 |
| P0-4 | 个人运行隔离、真实 RO、凭据代理、网络/端口和配额、撤权及状态存储隔离 | Agent/终端/应用均满足个人环境边界 |
| P1-1 | 前端角色导航、终端/进程/应用预览、个人用量、文件区域权限和管理员分配界面 | 普通用户拥有完整的个人环境使用入口 |
| P1-2 | Token 范围/Scope 收紧、旧 Token 处理、开发说明补齐 | Web 与 SDK 使用相同权限边界 |
| 验收 | 权限单测、API/SDK 集成检查、真实运行隔离验证 | 整个需求完成；不能省略 P0-4 |

重点验收场景：

- 普通用户通过 Web、直接 HTTP、SDK，携带旧 Owner/Admin 角色或管理 Scope，均不能创建三类资源、克隆空间或修改权限。
- 普通用户可在个人环境中创建/移动/删除文件与目录，执行脚本、构建项目、安装用户级依赖、启动/停止自己的应用并访问鉴权预览；上述操作无需获得 Pool/Workspace 管理角色。环境重启后应保留文件与依赖；依赖损坏时可由用户清理自己的内容后重装。
- 终端支持 UTF-8、窗口调整和中断；断开终端后已登记应用按策略继续运行，取消 Agent Run 不误杀独立应用。到达存活上限或禁用账号时，进程及子进程被回收，端口和资源名额释放；后台应用不能成为绕过 Token 吊销/授权到期的通道。
- A/B 同属一个 Pool，A 无法列表、检索、读写或订阅 B 的 Workspace、文件、会话、事件和快照；也不能通过 Pool 编辑权突破。
- 无共享访问权返回 404；已授权 RO 可以读，所有写入口返回 403；管理员指派 USER/RW 后可写，其他成员仍 RO；显式 Deny 覆盖 RW。
- 同一个共享空间的直接 API、Workspace 文件区和 Agent 挂载结果一致；挂载覆盖 RO 时该路径无法写。
- RW 撤销后，旧 Cookie、旧 Token、新任务和正在运行的任务/连接不能保留写权；无其他可见授权时不能继续读。
- Agent shell、交互终端、API 命令及后台应用通过绝对路径、目录链接和父路径不能访问其他用户目录，不能修改 RO 共享目录或平台控制文件；测试确认原共享文件未变更，不能只检查审计告警。用户仍可删除自己的内容，但不能破坏平台归属、挂载定义和 Workspace 记录。
- 用户从进程环境、DSH_HOME、配置和日志不能取得平台模型/管理/数据库密钥；模型代理拒绝越范围和被吊销的运行凭据。用户应用可使用自己的秘密，不能读取其他用户的应用秘密。
- 应用预览支持授权用户的 HTTP/WebSocket；其他用户、匿名请求、过期身份及范围不足的 Token 均被拒绝。应用不能取得平台登录 Cookie、借平台同源身份调用 API、绑定任意宿主端口或访问被禁止的控制面/元数据目标。
- CPU/内存/磁盘/进程/端口/并发超限有明确结果，不能拖垮其他个人环境；终端、包安装、Agent 和后台应用的写入均受真实存储配额约束。配置为不具备可靠隔离的部署时，所有普通用户执行入口均拒绝并报告环境未就绪。
- 普通 Token 无法提交整 Pool/空范围或管理 Scope；限定 Workspace 的 Token 无法直接读取未列入 Token 范围的共享空间。
- 默认 SDK Token 不可调用直接命令/终端入口；用户显式创建受限执行 Token 后可执行。缺少共享 Scope/范围的执行 Token 不能经挂载或复用 Web 环境扩大共享访问；只读 Token 无法开启 Agent/命令执行。
- 默认空间分配失败和并发登录不产生多个默认空间；管理员删除/归档默认空间后用户收到明确的重新分配提示。
- 管理员仍能创建、分配、授权与管理资源；已有显式拒绝策略不会被意外取消。

验证方式：复用现有 xUnit 权限与 Runtime 测试，更新与新业务规则冲突的旧用例；补充有实际越权意义的 API/SDK 场景，并在隔离测试环境验证真实 DSH 文件系统边界。前端执行现有 TypeScript/构建检查。项目没有 Playwright，禁止临时引入 Playwright 测试；所有为验证新开的进程必须记录并在结束时关闭，不替换现有运行进程。

本轮没有执行业务测试，因为没有修改业务代码。方案和后续实现按职责拆文件，单个新代码文件控制在 2000 行以内，不扩写现有长产品规格文档。

## 9. 业务与功能检查：确认的代码缺口

以下“确认”表示静态代码中可以定位到该缺口，不表示已向现有服务发送攻击请求或完成真实 DSH 复现。并发、文件系统和故障场景需要在隔离测试环境进一步验证。优先级：P0 为访问边界或数据破坏问题；P1 为上线使用前应修复的业务正确性问题；P2 为体验、维护和扩展优化。

### F01 · P0 · 文件删除可以接受区域根目录的别名

- 位置：`backend/src/Teager.Dsh.Infrastructure/Storage/FileStore.cs:134`。
- `Delete` 只拒绝规范化后为空的字符串，`Normalize` 不消解点路径；`Resolve(root, ".")` 返回 root，随后进入递归删除。`a/..` 在对应目录存在时也可能解析为 root。
- 影响：有该区域写权限的用户可以删除整个私有文件区或共享空间内容，而不是普通单个文件操作。目录删除也不会保存目录内所有文件的历史版本。
- 修复：在绝对路径解析后比较目标与区域根目录，禁止删除根本身及等价路径；拒绝不支持的点段/平台特殊路径，确保目录删除有明确的回收或不可恢复语义。不能仅扩充空字符串判断。
- 验收：临时目录中的空路径、`.`、`./`、`a/..` 均被拒绝，根目录及内容仍存在；正常子目录删除仍按权限工作。不要在现有数据目录复现。

### F02 · P0 · 共享文件 Scope 校验与区域解析不一致

- 位置：`backend/src/Teager.Dsh.Api/Controllers/WorkspacesController.cs:424`；`backend/src/Teager.Dsh.Infrastructure/Services/FileAccessService.cs:27`。
- Controller 对原始 `area.StartsWith("shared/")` 检查 `share:*`，服务随后执行 `Trim().Trim('/')` 再识别共享区域。`/shared/assets`、带外部空格的共享区域在前者不被识别，在后者被接受。
- 影响：具有 `files:read/write` 和相应资源权限、但没有 `share:read/write` 的 Token，可以经过该路径访问共享文件；资源 RO/RW 本身仍有校验，这不是匿名访问漏洞。
- 修复：先用唯一解析器规范化并分类，再同时检查文件 Scope、共享 Scope 和资源权限；所有文件操作使用同一个区域结果。

### F06 · P1 · CSRF 豁免依据头存在性，未依据实际认证方式

## 11. 合并后的实施优先级

1. **先关闭访问和数据破坏缺口**：F01—F05，以及个人 Workspace 隔离、管理员创建/管理上限、平台凭据代理和运行资源边界；R02/R06 的运行边界验证属于这一阶段。可靠隔离是普通用户自由执行的上线前置条件，终端与应用能力是本方案交付内容。
2. **再修复业务正确性**：F06—F18，优先原子任务名额、撤权、生命周期互斥、可靠恢复、Token 资源边界、配额、登录过期和长会话。
3. **配套用户与管理员体验**：权限导航、默认空间分配、终端/依赖指引/进程与应用预览、个人资源用量、共享/Pool 内容编辑授权、Token/开发说明及归档恢复入口，与后端能力同步交付。
4. **最后优化维护与扩展**：F19；依据实际部署确认 R01/R03/R05。多实例或多组织支持不能在缺少对应隔离的情况下默认宣称可用。

上述权限与业务修复已进入“仅使用”分支实现。迁移只在验证的临时数据库自动执行，现有运行服务和数据库没有被替换。部署时按部署说明备份并应用新增迁移。

## 12. 补充验收及已经具备的保护

新增验收覆盖：根目录等价路径删除保护、共享 area 等价写法的 Scope、受限管理员 Token、Cookie 与非 Bearer 头、双请求并发、请求幂等、快照损坏/数据库失败、归档恢复配额、keep=1 的历史版本恢复、Linux 大小写文件、超过 200 条的会话、登录过期跳转、SSE 断线续接、孤儿任务恢复、维护模式并发、超过 30 个资源的维护公平性。

本次调整另增加个人环境正向验收：文件管理、交互终端、脚本/构建、依赖持久化、后台应用、进程中断与回收、HTTP/WebSocket 预览。负向验收覆盖跨用户目录/进程/秘密、RO 共享实际不可写、平台密钥不可读、受限 Token 的执行挂载不扩权、网络控制面隔离、资源超限和授权撤销后的持续执行。

已有保护应保留：全局登录要求、HttpOnly/SameSite Cookie、密码哈希与禁用账号登录限制、Token 摘要存储和每请求过期/吊销检查、普通文件路径越界/链接检查、共享文件 API 的 RO/RW 检查、显式 Deny、挂载权限只降不升、前端 Markdown 清洗，以及 FileManager 使用后端区域 writable。此次发现的是这些保护的覆盖缺口和流程不一致，不能据此认定平台完全没有权限控制。

实施与验收结果见 [交付与验证记录](usage-only-verification.md)。文档以 UTF-8 保存；临时测试进程、容器和数据库在验证结束后清理。原有业务进程保持运行。
